Claude Code 常用命令速查

Claude Code 的命令体系覆盖了对话管理、开发工作流、权限控制和自动化四个层面。本文逐一梳理各命令的功能、执行结果和典型用法。

对话管理

/clear

结束当前会话，开启全新对话窗口。

执行后对话历史全部清空，但环境上下文和长期记忆会在新一轮自动重新注入，System prompt 不变。代价是当前对话中建立的所有上下文理解随之丢失。

用法：每个独立任务开始前执行。修完 bug A 后 /clear，再开始修 bug B，防止上下文污染。

/compact

当对话接近 token 上限时，用一个独立 LLM 调用将整段对话历史总结为结构化摘要，替换原对话。

压缩后对话从数万条消息缩减为三条：摘要、恢复上下文、提示。Token 占用降低约 70%。摘要按九个维度结构化：任务意图、技术概念、文件路径、错误与修复、解决过程、用户原话、待办、当前工作、下一步。恢复上下文包含最近读过的文件快照、已激活技能和工具列表。LLM 被告知需要原文时重新 ReadFile。

触发时机有两种：手动执行 /compact，或 token 接近上限时自动触发，用户无感知。

claude -c

从磁盘恢复最近一次对话。Claude Code 自动保存 session，包括对话历史、上下文和项目状态。重新打开后 Claude 看到完整的前次对话，像没关过一样继续工作。

适用场景：关机或重启后继续之前的开发。

开发工作流

/plan

切换到只读规划模式。LLM 只能读代码和搜索，不允许编辑文件或执行修改性命令。

进入后工具集收缩为：读文件、搜索、AskUserQuestion、Explore/Plan 子 Agent。唯一可写的文件是计划文件。System prompt 替换为五阶段流程：探索、设计、审查、输出、提交审批。

典型流程：

用户: /plan 重构认证模块
Claude: [进入 Plan 模式]
  → 启动 Explore Agent 并行研究代码
  → 启动 Plan Agent 设计方案
  → 输出计划到 plan 文件
  → ExitPlanMode → 用户审批

用户: [审批通过]
Claude: [退出 Plan 模式，按计划逐步实施]

/rewind

撤销最近的对话轮次和对应的代码修改，回到之前保存的检查点。

与手动 git checkout 的关键区别：git checkout 只回退文件，LLM 在对话中仍记得错误尝试，后续推理可能被误导。/rewind 同时回退对话历史和文件状态，LLM 完全忘记刚才的尝试。

适用场景：改完发现方向错了，或 Claude 连续几轮在错误轨道上，回到分叉点重新来。

/init

自动分析项目结构，生成或追加 CLAUDE.md。

分析内容包括：项目技术栈（从 package.json、pyproject.toml、go.mod 等自动检测）、目录结构及各目录职责、构建/测试/部署命令、编码规范和约定。

用法：新项目执行 /init 自动生成；后续再执行可追加新模块说明；也可以手动编辑 CLAUDE.md，Claude 每轮都会读取。

/review

审查当前分支相对于 main 的 diff，按多个维度给出意见。

审查维度：正确性 bug（空指针、边界条件、并发问题）、简化机会（重复代码、多余抽象）、效率问题（不必要的循环、N+1 查询）、安全风险（注入、权限绕过）。

参数说明：

参数 效果
/review 审查当前 diff，输出报告
/review --comment 作为 PR 评论直接贴到 GitHub
/review --fix 自动修复高置信度问题

输出为结构化审查报告，每个发现包含严重程度、文件路径、行号和修复建议。

辅助交互

/btw

在对话中插入一条低优先级的附加信息，不打断 Claude 当前工作流。

与普通输入的区别：普通输入会被理解为主任务切换，Claude 可能放下手里的事；/btw 注入的消息以 side note 形式存在，Claude 识别为”做完当前事情后再考虑”。

/mcp

管理 MCP 服务器，即外部工具提供者。

命令 效果
/mcp list 列出所有已连接/未连接的 MCP server
/mcp connect <name> 连接一个 MCP server，加载其工具
/mcp disconnect <name> 断开连接
/mcp status 查看连接状态

连接后，MCP server 提供的工具以 mcp__ 前缀出现在工具列表中，可与内置工具一样调用。

Shift + Tab

循环切换当前 session 的权限模式，无需手动改配置文件。

切换顺序：Default（读放行，写需确认，命令需确认）→ AcceptEdits（读放行，写放行，命令需确认）→ DontAsk（全部放行）→ Plan（只读，全拒绝）→ 回到 Default。

即时生效，影响当轮的工具权限检查。典型用法：默认模式下谨慎确认每次写文件，改到熟悉的模块后切换 AcceptEdits 加速。

自动化

claude -p

非交互的一次性模式。发一个 prompt，Claude 完成后输出结果到 stdout，随即退出。

# CI 自动修复
claude -p "根据以下测试失败日志修复 bug: $(cat test-output.log)" --permission-mode dontAsk

# PR 自动审查
git diff main | claude -p "审查这个 diff，输出 Markdown 格式的审查报告"

# Git hook 预检查
claude -p "检查当前修改是否有安全风险" --permission-mode plan --max-turns 5

与交互模式的对比：

维度 claude（交互模式） claude -p（脚本模式）
对话 多轮，持续交互 单次，返回结果即退出
用户确认 可能需要 通常配 –permission-mode dontAsk
输出 终端对话中 stdout
适用 手动开发、探索 CI/CD、脚本、自动化
