MinerU 解析引擎技术剖析：Pipeline、VLM 与 Hybrid

MinerU 是 OpenDataLab 开源的文档解析工具，将 PDF、图片等文档转换为结构化 Markdown 和 JSON。当前版本提供三种解析后端：Pipeline（多模型管线）、VLM（视觉语言模型端到端）、Hybrid（混合引擎）。本文梳理各后端的模型组成，并重点展开 Pipeline 的实现细节。

一、三大后端概览

MinerU 的三种后端代表了文档解析的两代技术路线：Pipeline 是经典的”检测-识别”多模型串联方案，VLM 是端到端多模态大模型方案，Hybrid 则将两者融合，按页面特征动态路由。

后端 核心思路 硬件要求 适用场景
Pipeline 多个专用小模型分步处理 CPU 可跑，GPU 加速 扫描件、OCR 密集、低资源环境
VLM 单个视觉语言模型端到端 通常需要 GPU 复杂版面、图文混排、多语言
Hybrid Pipeline + VLM 动态融合 取决于 effort 档位 通用场景，兼顾速度与精度

二、Pipeline 后端：多模型管线详解

Pipeline 是 MinerU 最早也最成熟的后端。它将文档解析拆分为多个独立子任务，每个子任务由一个专用模型负责，最终将各模型输出组装为结构化结果。

2.1 整体处理流程

一页 PDF 从输入到输出经历以下阶段：

PDF 输入
  → 页面分类（文本型 / 扫描型 / 混合型）
  → 页面渲染为图像
  → 版面检测（Layout Detection）
  → 文本提取 / OCR 识别
  → 公式检测 + 公式识别
  → 表格结构识别
  → 阅读顺序排序
  → 结构化输出（Middle JSON → Markdown / JSON）

2.2 页面分类与渲染

Pipeline 首先判断 PDF 页面类型：

  • 文本型 PDF：页面内嵌可提取的文字流（通过 PyMuPDF / fitz 检测），直接走文字提取路径。
  • 扫描型 PDF：页面无文字流，渲染为图片后走全量 OCR + 版面检测。
  • 混合型 PDF：部分页面有文字流、部分没有，逐页判定分别处理。

渲染阶段将 PDF 页面光栅化为图像（通常 300 DPI），同时完成方向校正（处理旋转 90°/180°/270° 的页面）。

2.3 版面检测

版面检测模型对渲染后的页面图像做目标检测，输出各元素的类别和边界框。

当前模型：PP-DocLayout V2（早期版本使用 DocLayout-YOLO，已在 3.x 版本中替换）。

版面分析模块 - PaddleOCR 文档

PP-DocLayout V2 支持 25 种元素类别检测，包括：标题（多级）、正文段落、图片、表格、公式（行内/行间）、页眉、页脚、脚注、目录、代码块等。检测结果是一组带类别标签和置信度的 bounding box。

2.4 文本提取与 OCR

文本获取采用分流策略：

  • 文本型页面：直接用 PyMuPDF 从 PDF 对象树中提取文字及其坐标，无需 OCR。
  • 扫描型页面 / 图像区域：将对应裁剪区域送入 OCR 模型。

OCR 模型：PP-OCRv6（3.x 版本从 PaddleOCR 升级而来，通过 PytorchPaddleOCR 封装调用）。

PP-OCRv6 的处理分三步：文字行检测（DB 算法）→ 方向纠正 → 字符识别（CRNN/SVTR）。支持 109 种语言，对中文场景有专门优化（ch 模型路由）。

2.5 公式处理

公式处理分两阶段：

检测阶段：定位页面中的公式区域。早期使用 YOLOv8 MFD（Math Formula Detection）模型，新版已整合进版面检测模型统一处理。

识别阶段：将公式区域裁剪为图像，送入公式识别模型输出 LaTeX 源码。

当前识别模型为 UniMerNet（备选 PP-FormulaNet）。UniMerNet 基于 Transformer 编码器-解码器架构，输入公式图像，自回归生成 LaTeX 序列。支持行间公式和行内公式，输出直接嵌入 Markdown 的 $$...$$ 或 $...$ 定界符中。

2.6 表格识别

表格区域经版面检测定位后，送入表格结构识别模型还原行列关系。

当前模型：SLANET + UNet（早期版本使用 RapidTable / StructEqTable）。

处理流程：

  1. UNet 做表格线检测，识别横线、竖线及单元格边界。
  2. SLANET（Structure Label Attention Network）基于视觉特征和结构注意力机制，输出表格的 HTML 结构标签序列（<table>, <tr>, <td>, colspan, rowspan 等）。
  3. 后处理阶段将单元格内容与结构对齐，处理合并单元格、跨页表格拼接。

最终输出 HTML 格式表格，嵌入 Markdown 中。

2.7 阅读顺序排序

多栏文档中，版面检测输出的区块是无序的，需要恢复人类阅读顺序。

早期方案：LayoutReader（基于 LayoutLM 的序列标注模型，用 ReadingBank 数据集训练，将排序建模为序列标注问题）。新版已移除该独立模型。

当前方案：基于规则的启发式排序——

  1. 判断页面栏数（单栏 / 双栏 / 多栏）。
  2. 栏内按纵向坐标（y 值）从上到下排序。
  3. 栏间按横向坐标（x 值）从左到右排序。
  4. 图表插入其相邻引用文本附近（基于位置邻近度）。
  5. 页眉、页脚、脚注单独处理，不混入正文流。

2.8 模型调度与性能优化

Pipeline 在工程层面做了多项优化：

  • ModelSingleton / AtomModelSingleton：线程安全的模型单例缓存，避免重复加载权重。
  • 窗口化处理：大文档按 64 页/窗口分批处理，控制内存峰值。
  • 动态批处理：batch_ratio 支持 1x~16x，根据 GPU 显存动态调整推理 batch size。
  • 核心入口文件：pipeline_analyze.py（单文档）、batch_analyze.py（批量）、model_init.py（模型初始化）。

2.9 Pipeline 子模型汇总

子任务 当前模型 历史模型（已移除）
版面检测 PP-DocLayout V2 DocLayout-YOLO
公式检测 整合进版面检测 YOLOv8 MFD
公式识别 UniMerNet / PP-FormulaNet —
表格识别 SLANET + UNet RapidTable / StructEqTable
OCR PP-OCRv6 PaddleOCR (早期)
阅读顺序 规则启发式 LayoutReader

三、VLM 后端：视觉语言模型端到端

VLM 后端用单个多模态大模型替代整条 Pipeline，输入页面图像，直接输出结构化 Markdown。

3.1 模型版本迭代

版本 参数量 状态
MinerU2.0-2505-0.9B 0.9B 上一代，已替代
MinerU2.5-Pro-2604-1.2B 1.2B 中间版本
MinerU2.5-Pro-2605-1.2B 1.2B 当前最新（3.3+）

命名规则：MinerU{大版本}-{年月}-{参数量}。2605 即 2026 年 5 月发布。

3.2 推理运行时

VLM 模型本身相同，但可选择不同推理引擎：

运行时 特点
vLLM 高吞吐，PagedAttention，适合服务端批量推理
LMDeploy 国产推理框架，TurboMind 内核，量化支持好
MLX Apple Silicon 原生，比 transformers 快 100%–200%
HuggingFace Transformers 通用性最好，速度最慢，适合调试

3.3 适用场景

VLM 端到端方案在复杂版面（多栏混排、图表嵌套、手写体）和多语言文档上效果最好，因为模型能像人一样”看懂”页面整体结构，而非依赖检测框的机械拼接。代价是需要 GPU 且单页推理时间较长。

四、Hybrid 后端：混合引擎

Hybrid 是 3.x 版本推出的融合方案，核心思路：文本型 PDF 直接抽取文字（零 OCR 损耗），扫描型 PDF 和复杂元素交给 VLM 理解。

4.1 两档 effort

档位 Benchmark 分数 速度 图片分析 适用场景
medium（默认） 95.26 比 high 快 35%–220% 不支持 日常文档、速度优先
high 95.39 较慢 支持 图表分析、精度优先

作为对比，纯 VLM 后端的 benchmark 分数为 95.30。Hybrid-high 以组合策略超越了纯 VLM。

4.2 路由逻辑

  • 文本型 PDF 页面：直接提取内嵌文字，跳过 OCR 和 VLM，速度极快。
  • 扫描型 PDF 页面：走 OCR（109 种语言）+ VLM 版面理解。
  • 图片分析（effort=high）：对文档中的图表、插图调用 VLM 生成描述。

五、选型建议

场景 推荐后端 理由
无 GPU、批量扫描件 Pipeline CPU 可跑，资源占用低
有 GPU、版面复杂 VLM 端到端理解，复杂排版效果最好
通用场景、追求性价比 Hybrid medium 默认即可，速度快精度高
需要图表内容分析 Hybrid high 唯一支持 image analysis 的模式
Apple Silicon 本地 VLM + MLX 原生加速，体验最好

六、版本演进趋势

从版本迭代可以看出 MinerU 的技术方向：Pipeline 中的独立小模型逐步被裁剪（DocLayout-YOLO、YOLOv8 MFD、LayoutReader 均已移除），能力向 VLM 收归。Hybrid 作为过渡方案平衡了精度和部署门槛。长远看，VLM 端到端是主线，Pipeline 将更多承担”轻量 fallback”角色。
