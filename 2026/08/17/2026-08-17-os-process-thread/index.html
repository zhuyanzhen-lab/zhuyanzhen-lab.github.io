操作系统基础（一）：进程与线程

操作系统
发布日期:   2026-08-17

操作系统为用户程序提供了一套抽象：进程与线程。它们分别是资源分配和 CPU 调度的基本单位，理解二者的关系与区别是掌握操作系统并发机制的基础。

进程

进程（Process）是操作系统进行资源分配的最小单位。每个进程拥有独立的虚拟地址空间、文件描述符表、信号处理函数等系统资源。从内核视角看，进程由一段可执行代码、数据段、堆栈以及一个进程控制块（PCB）组成。

PCB 是内核对进程的管理结构，包含以下关键字段：

  • 进程标识符（PID）：唯一标识一个进程的整数。
  • 进程状态：当前所处的执行阶段。
  • 程序计数器：下一条待执行指令的虚拟地址。
  • 寄存器上下文：通用寄存器、栈指针、状态寄存器等。
  • 内存管理信息：页表基址、段表等。
  • I/O 状态：打开的文件列表、分配的设备等。

进程的生命周期与状态转换

进程在其生命周期中经历五种状态：

       ┌──────────┐
       │   创建    │
       └────┬─────┘
            │ 初始化完成
            ▼
       ┌──────────┐    时间片用完     ┌──────────┐
  ┌───▶│   就绪    │◄───────────────│   运行    │
  │    └──────────┘                 └────┬─────┘
  │         ▲                            │
  │         │  I/O 完成                  │ 请求 I/O
  │         │                            ▼
  │    ┌──────────┐                 ┌──────────┐
  └────│   阻塞    │◄──────────────│   阻塞    │
       └──────────┘                 └──────────┘
                                         │
                                    进程结束
                                         ▼
                                    ┌──────────┐
                                    │   终止    │
                                    └──────────┘

各状态的含义：

  • 创建态：内核正在为进程分配资源、初始化 PCB。
  • 就绪态：进程已具备运行条件，等待 CPU 分配。多个就绪进程排成就绪队列。
  • 运行态：进程正在 CPU 上执行指令。单核 CPU 任意时刻只有一个进程处于运行态。
  • 阻塞态：进程因等待某个事件（I/O 完成、信号量 P 操作、子进程结束等）而主动让出 CPU。
  • 终止态：进程执行完毕或因异常被内核回收。

状态转换的触发条件：

  • 就绪 → 运行：调度器选中该进程，分配 CPU。
  • 运行 → 就绪：时间片耗尽，或被更高优先级进程抢占。
  • 运行 → 阻塞：进程主动请求 I/O 或等待某事件。
  • 阻塞 → 就绪：等待的事件完成，进程被唤醒。

fork() 系统调用

fork() 是 Unix/Linux 中创建进程的唯一系统调用。调用一次，返回两次：父进程返回子进程的 PID，子进程返回 0。

pid_t pid = fork();
if (pid < 0) {
    // fork 失败
} else if (pid == 0) {
    // 子进程执行路径
    exec("/bin/ls");  // 通常配合 exec 族替换执行镜像
} else {
    // 父进程执行路径
    wait(NULL);  // 等待子进程结束
}

fork() 之后，子进程获得父进程地址空间的完整副本。为避免大量数据拷贝，现代操作系统采用写时复制（Copy-on-Write, COW）机制：父子进程初始共享同一组物理页面，仅当某一方写入时才由内核复制该页面。这大幅降低了 fork() 的时间和空间开销。

fork() 复制的内容包括：代码段、数据段、堆、栈、文件描述符表（子进程继承父进程打开的文件）、信号处理设置、当前工作目录等。但以下内容不复制：进程 ID、父进程 ID、内存锁、未决信号、资源统计等。

特殊进程

僵尸进程（Zombie Process）：子进程先于父进程退出，内核已回收其大部分资源（内存、文件描述符等），但进程描述符（PCB 中的退出状态码）仍保留在进程表中，等待父进程调用 wait() 或 waitpid() 读取。此时该进程处于”僵尸”状态，占用一个 PID 和进程表项。

如果父进程始终不调用 wait()，僵尸进程会持续累积，最终耗尽系统的 PID 资源。解决方法：父进程注册 SIGCHLD 信号处理函数，在函数中调用 wait() 回收子进程；或者直接忽略 SIGCHLD（signal(SIGCHLD, SIG_IGN)），内核会自动回收。

孤儿进程（Orphan Process）：父进程先于子进程退出，子进程失去父进程。此时内核会将孤儿进程的父进程重新指向 init 进程（PID=1）或子 reaper 进程。init 进程会自动调用 wait() 回收孤儿进程，因此孤儿进程不会变成僵尸进程。

守护进程（Daemon Process）：运行在后台、脱离控制终端的特殊进程。创建步骤：fork() 后父进程退出 → 子进程调用 setsid() 创建新会话、脱离原终端 → 修改工作目录为根目录 → 重定向标准输入/输出/错误到 /dev/null → 关闭不需要的文件描述符。典型的守护进程如 sshd、cron、systemd。

线程

线程（Thread）是 CPU 调度的基本单位，存在于进程内部。一个进程可以包含多个线程，它们共享进程的地址空间（代码段、数据段、堆）和系统资源（文件描述符、信号设置等），但每个线程维护独立的：

  • 线程栈：用于函数调用、局部变量。
  • 线程控制块（TCB）：包含程序计数器、寄存器上下文、线程状态、信号掩码等。
  • 线程本地存储（TLS）：线程私有的数据区域。

引入线程的动机：单进程内多个任务需要并发执行时，多进程方案面临通信开销大、资源共享困难的问题。线程共享同一地址空间，天然支持数据共享，且切换开销远小于进程。

进程与线程的核心区别

维度 进程 线程
资源分配 拥有独立的地址空间和资源 共享所属进程的资源
CPU 调度 不是调度单位 是 CPU 调度的基本单位
地址空间 独立虚拟地址空间 共享进程地址空间
切换开销 大（需切换页表、刷新 TLB） 小（仅切换寄存器和栈）
隔离性 高，一个进程崩溃不影响其他进程 低，一个线程崩溃可能导致整个进程终止
通信方式 需 IPC 机制（管道、共享内存等） 直接读写共享内存，需同步机制
创建/销毁开销 大 小

多线程的优势与问题

优势：

  • 并行执行：多核 CPU 上多个线程可同时运行，提升计算密集型任务的吞吐量。
  • 响应性：一个线程阻塞（如等待 I/O）时，其他线程继续执行，不会阻塞整个进程。
  • 资源共享：线程天然共享进程内存，无需额外的 IPC 机制。
  • 经济性：创建和切换线程的开销远小于进程。

问题：

  • 数据竞争：多个线程同时读写共享变量时，结果取决于执行时序，导致不确定行为。
  • 死锁：多个线程互相持有对方需要的锁，导致所有线程都无法继续。
  • 上下文切换：线程数过多时，频繁切换消耗大量 CPU 时间。
  • 调试困难：并发程序的执行路径不确定，bug 难以复现。

协程

协程（Coroutine）是运行在用户态的轻量级执行单元，调度完全由用户程序控制，不涉及内核态切换。协程拥有独立的栈和寄存器上下文，但共享所属线程的堆和地址空间。

协程与线程的对比：

维度 线程 协程
调度方 内核 用户程序
切换开销 需要内核态切换 纯用户态切换，开销极小
栈大小 通常 MB 级（Linux 默认 8MB） 通常 KB 级，可动态增长
并发能力 受系统资源限制，数千到数万 轻松创建数十万
并行能力 多核可并行 单线程内并发，不可并行（除非配合多线程）
适用场景 CPU 密集型 + I/O 密集型 I/O 密集型（大量网络请求、异步操作）

协程的核心价值在于：用同步的写法实现异步的逻辑，避免回调地狱。典型实现包括 Python 的 asyncio、Go 的 goroutine、Kotlin 的 coroutine、JavaScript 的 async/await。

上下文切换

上下文切换（Context Switch）是 CPU 从一个执行单元切换到另一个时，保存当前状态、恢复目标状态的过程。

进程上下文切换包含以下步骤：

  1. 保存当前进程的 CPU 寄存器值（程序计数器、通用寄存器等）到其 PCB。
  2. 将当前进程状态从”运行”改为”就绪”或”阻塞”。
  3. 调度器从就绪队列选择下一个进程。
  4. 从新进程的 PCB 恢复寄存器值。
  5. 切换页表基址寄存器（如 x86 的 CR3），更新虚拟地址映射。
  6. 刷新 TLB（Translation Lookaside Buffer），因为旧的地址翻译已失效。
  7. 将控制权交给新进程。

线程上下文切换的流程类似，但省去了第 5、6 步——同一进程内的线程共享页表，不需要切换地址空间和刷新 TLB。这是线程切换远快于进程切换的根本原因。

上下文切换的开销由两部分组成：

  • 直接开销：保存/恢复寄存器、切换栈指针、更新内核数据结构。
  • 间接开销：TLB 刷新导致的页表重走、CPU 缓存（L1/L2/L3）失效导致的缓存未命中。后者往往比前者更大。

进程间通信（IPC）

进程间通信是指不同进程之间交换数据的机制。由于进程拥有独立的地址空间，无法直接访问对方的内存，必须借助内核提供的中间媒介。

管道（Pipe）

匿名管道：内核维护的一块环形缓冲区，仅存在于内存中。只能用于具有亲缘关系的进程（父子进程）。半双工通信，数据只能单向流动。创建方式：pipe(fd)，返回两个文件描述符 fd[0]（读端）和 fd[1]（写端）。

命名管道（FIFO）：在文件系统中有一个路径名，任何进程都可以通过打开该路径进行通信，不要求亲缘关系。同样是半双工。创建方式：mkfifo("mypipe", 0666)。

消息队列（Message Queue）

内核中维护的一个链表结构，存储具有特定类型的消息块。进程通过 msgsnd() 发送消息、msgrcv() 接收消息。优点是可以按消息类型选择性接收，缺点是需要用户态和内核态之间的数据拷贝，且消息大小受内核限制。

共享内存（Shared Memory）

内核分配一块物理内存，多个进程将其映射到各自的虚拟地址空间。进程直接读写这块内存，无需内核拷贝，是所有 IPC 方式中速度最快的。

// 创建共享内存段
int shmid = shmget(key, size, IPC_CREAT | 0666);
// 映射到当前进程地址空间
void *ptr = shmat(shmid, NULL, 0);
// 读写 ptr 指向的内存...
// 分离
shmdt(ptr);
// 删除共享内存段
shmctl(shmid, IPC_RMID, NULL);

共享内存本身不提供同步机制，需要配合信号量（Semaphore）使用，防止多个进程同时写入导致数据不一致。

信号量（Semaphore）

一个计数器，用于控制多个进程对共享资源的访问。核心操作是两个原子操作：

  • P 操作（wait/down）：计数器减 1。若结果 < 0，进程阻塞等待。
  • V 操作（signal/up）：计数器加 1。若结果 ≤ 0，唤醒一个等待的进程。

二值信号量（取值 0/1）可用作互斥锁；计数信号量（取值任意非负整数）用于控制可分配的资源数量。

信号（Signal）

一种异步通知机制，用于告知进程某个系统事件发生。信号由内核发送，进程可以捕获、忽略或执行默认动作。常见信号：

  • SIGINT（Ctrl+C）：中断进程。
  • SIGKILL：强制终止进程，不可捕获。
  • SIGTERM：请求终止进程，可捕获并做清理。
  • SIGCHLD：子进程状态变化时通知父进程。
  • SIGSEGV：段错误，访问非法内存地址。

Socket

支持本地或跨网络的进程间通信。基于文件描述符抽象，提供流式（TCP）和数据报（UDP）两种通信模式。本地通信可使用 Unix Domain Socket，性能优于 TCP 回环地址。

各 IPC 方式对比

方式 通信方向 适用进程关系 速度 数据格式
匿名管道 半双工 亲缘进程 中 字节流
命名管道 半双工 任意进程 中 字节流
消息队列 全双工 任意进程 中 消息块
共享内存 双向 任意进程 最快 无限制
信号 单向通知 任意进程 — 信号编号
Socket 全双工 任意进程（含跨主机） 中 字节流/数据报

线程同步机制

多线程共享地址空间带来数据竞争问题。当多个线程同时访问共享数据且至少一个执行写操作时，必须引入同步机制。

互斥锁（Mutex）

保证同一时刻只有一个线程能访问临界资源。线程获取锁成功则进入临界区，其他线程阻塞等待。释放锁后，等待队列中的一个线程被唤醒。

pthread_mutex_t mutex = PTHREAD_MUTEX_INITIALIZER;

pthread_mutex_lock(&mutex);    // 加锁
// 临界区：访问共享资源
pthread_mutex_unlock(&mutex);  // 解锁

读写锁（Read-Write Lock）

允许多个线程同时读取共享资源，但写入时独占。适合读多写少的场景。

  • 读锁：多个线程可同时持有。
  • 写锁：独占，与读锁和其他写锁互斥。

自旋锁（Spinlock）

线程在获取锁时不进入阻塞态，而是持续循环检查锁状态（忙等待）。适用于临界区极小、锁持有时间极短的场景，因为避免了线程切换的开销。但在单核 CPU 上自旋锁会浪费 CPU 时间。

// 自旋锁的伪代码实现
while (!atomic_compare_and_swap(&lock, 0, 1)) {
    // 忙等待，不断重试
}
// 进入临界区
lock = 0;  // 释放锁

条件变量（Condition Variable）

允许线程等待某个条件成立。通常与互斥锁配合使用：

pthread_mutex_t mutex = PTHREAD_MUTEX_INITIALIZER;
pthread_cond_t cond = PTHREAD_COND_INITIALIZER;

// 等待条件成立
pthread_mutex_lock(&mutex);
while (condition_is_false) {
    pthread_cond_wait(&cond, &mutex);  // 阻塞等待，同时释放锁
}
// 条件成立，访问资源
pthread_mutex_unlock(&mutex);

// 通知等待线程
pthread_cond_signal(&cond);   // 唤醒一个
pthread_cond_broadcast(&cond); // 唤醒所有

信号量（Semaphore）

用于线程间同步时，与进程间通信中的信号量原理相同。二值信号量实现互斥，计数信号量控制并发访问数量。

进程调度算法

调度算法决定就绪队列中哪个进程获得 CPU。评价标准包括：CPU 利用率、吞吐量、周转时间、等待时间、响应时间。

先来先服务（FCFS）

按进程到达就绪队列的先后顺序分配 CPU。实现简单，但短进程可能需要等待长进程，平均等待时间较长（护航效应）。

最短作业优先（SJF）

优先调度预计执行时间最短的进程。可以证明在平均等待时间上是最优的。但长进程可能持续被短进程抢占，产生饥饿问题。预计执行时间通常基于历史数据的指数滑动平均估算。

高响应比优先（HRRN）

响应比 = (等待时间 + 服务时间) / 服务时间。等待时间越长，响应比越高，因此兼顾了短进程和长进程。缺点是每次调度需要计算所有就绪进程的响应比，开销较大。

时间片轮转（RR）

每个进程分配一个固定时间片（通常 10-100ms）。时间片用完后，进程被抢占并放到就绪队列末尾。时间片大小的选择是关键：太小导致频繁上下文切换，太大则退化为 FCFS。

优先级调度（HPF）

为每个进程分配优先级，优先调度最高优先级的进程。可分为静态优先级（创建时确定）和动态优先级（运行时根据行为调整，如 Linux 的 nice 值）。低优先级进程可能饥饿，解决方案是老化（Aging）：随等待时间增加逐步提升优先级。

多级反馈队列

综合时间片轮转和优先级调度的方案。设置多个就绪队列，每个队列对应不同优先级和时间片大小：

  • 队列 0：优先级最高，时间片最小（如 8ms）。
  • 队列 1：优先级次之，时间片较大（如 16ms）。
  • 队列 2：优先级更低，时间片更大。
  • …以此类推。

新进程进入最高优先级队列。若在一个时间片内完成，直接退出；若未完成，降级到下一个队列。低优先级队列只有在所有高优先级队列为空时才获得 CPU。

该算法的优势：短进程在高优先级队列快速完成，长进程在低优先级队列以较大时间片运行（接近 FCFS），兼顾了交互性和吞吐量。Linux 的 CFS（Completely Fair Scheduler）是其变体。

知识点总结

进程与线程是操作系统并发的两个核心抽象。进程拥有独立地址空间，是资源分配单位；线程共享进程资源，是 CPU 调度单位。协程进一步将调度下沉到用户态，适合 I/O 密集场景。

进程间通信需要内核中介，共享内存最快但需额外同步，管道和消息队列使用简单但有拷贝开销。线程间直接读写共享内存，但必须用互斥锁、读写锁、条件变量等同步机制保证数据一致性。

上下文切换的核心开销来自地址空间切换（页表 + TLB 刷新）和缓存失效，因此线程切换远快于进程切换。调度算法在公平性、吞吐量、响应时间之间权衡，多级反馈队列是实践中最通用的方案。
